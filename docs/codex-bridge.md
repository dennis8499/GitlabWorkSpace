# 使用 Codex 任務工作台

## 新增任務與管理

可從 Issue、MR、專案或 Skills／BMAD 的執行按鈕開啟任務準備；自由任務可在 Codex 頁按「建立 Codex 任務」，或使用同名原生命令。準備頁保存需求、來源、Repo、工作目錄、模型與思考強度，逐項檢查前置條件。只有按「開始執行」才排入任務；模型及強度在頁內選擇，沿用同帳號、專案及工作類型的有效偏好。原生 Reviewer 的恢復維持原 request 與執行設定。

缺少 Repo、WorkflowKit、登入或 Windows sandbox 時，先使用檢查項目的修復入口，再回 Codex 繼續同一份準備並按「重新檢查」。離開畫面或重新載入會保留內容。兩個視窗修改同一份設定時，畫面保留尚未同步的輸入，提供「套用我的設定」與「使用目前保存設定」，不會用舊檢查覆寫新資料。

未送出的訊息、一般問題／工具表單回答、MR 回覆及準備輸入，另依帳號與專案保存在本機。顯示保存完成後，即使關閉工作台或重新啟動 VS Code，也能恢復；密碼等秘密欄位只留在目前畫面記憶體。多視窗修改不同草稿可各自保存；同一筆內容發生衝突時保留兩份，供明確選擇或複製，不會用較晚抵達的舊內容覆寫。恢復草稿不會自動送出訊息、回答或發布。

重新檢查發現來源改變時，準備頁列出前後 SHA、目標 SHA、Issue 標題／更新時間及已選討論的變更提示；須明確確認更新的來源才能開始。重查相同版本不會清除尚未確認的差異，再次變更則重新要求確認。已停止且執行、清理、發布及訊息結果明確的 Issue／MR／Wiki 任務，可按「重新準備」另開草稿，保留需求、Repo、模型與返回位置，並以原任務來源比較；原任務及其他未完成草稿保留，也不會直接排入執行。已送出的任務仍使用既有固定來源及排隊前核對規則。

自由任務不需要 WorkflowKit，也可使用「將選取文字帶入 Codex 任務」。文字檔與選取區塊固定為送出時的快照，每項最多 32,000 字、合計最多 128,000 字及 10 項；送出前可預覽，其他 Repo 的檔案會被拒絕。

每個任務獨立保存模型與強度，後續傳送及恢復沿用選擇；對話分支繼承來源設定，重新同步的新 request 可重新選擇。Codex 頁的「模型與使用量」分別顯示任務設定與實際執行資訊。這些選擇不會修改全域 Codex 設定。

任務清單支援搜尋、狀態／Repo 篩選與顯示封存。「更多操作」提供重新命名、釘選、封存、排隊順序、診斷、對話分支及目標設定；封存只隱藏管理紀錄。對話分支建立獨立且暫停的自由任務，保留原對話，也不繼承原工作流程的發布權限。

執行資訊顯示模型回報的計畫、Token、額度及工具狀態；無資料時標示未知。差異選單可查看模型回報快照，或開啟原生暫存／工作目錄比較，後者可能包含人工修改。檔案變更可直接開啟對應檔案。大量對話沿用虛擬化，Host 與 Webview 的歷史視窗各有 32 MiB 預算，卸載內容可重新讀取。

## 核對結果及執行上限

「核對任務狀態」只讀取已保存的回合、程序停止收據與發布標記，不呼叫模型，也不重送操作。執行、清理及發布分開呈現；缺少可靠證據時保留待核對狀態及執行鎖。程序關閉沿用一般任務 5 秒、工作流程 30 秒等待，再最多等待 5 秒終止確認。

單筆損壞紀錄不影響其他歷史的顯示；原件保留，畫面列出識別與修復入口，並暫停新派發。v1 紀錄仍可讀取，首次更新時原子升級並保留 `.v1-backup`；升級時請重載所有 VS Code 視窗。

使用者設定 `gitlabWorkspace.codex.maxConcurrentTasks` 預設 1，可選 2。本機各視窗共用執行槽，Repo、寫入目錄、安裝根、runtime 及 Git common directory 有交集的任務仍序列執行；同 Repo 的多個 worktree 也不會繞過互斥。等待某個資源的任務不阻擋其他獨立資源，排隊期間可調整本視窗的順序。

Auto-Accept 保留預設 OFF 與既有總開關，可額外勾選命令、檔案修改及額外權限。範圍設定會保存；Host 重開後總開關仍 OFF。問題、MCP 表單及登入連結繼續由使用者處理。診斷可先在編輯器預覽再另存，僅包含版本、狀態、能力與 RPC 耗時，不包含提示詞、原始 stderr 或機密。

## 隔離開發、交接與增量更新

Issue 預設勾選「在隔離 worktree 執行」，可在準備時明確改為原 Repo。隔離任務在受管理的獨立目錄建立工作分支，BMAD 工作根目錄、產物、修改與測試均指向該目錄；原 Repo 的分支與未提交內容保留。成果頁可開啟隔離工作區。恢復會核對 Git 所屬及分支；既有任務沿用原執行位置。更多操作可移除已停止且沒有未保存變更或 Git 忽略檔案的 worktree，保留分支上的提交。

Issue 成果就緒後可產生 MR 描述草稿，直接在成果頁檢閱及複製。檢閱並手動暫存差異後，可在同一工作台開啟預填的 CommitReviewer 準備流程。交接前核對成果指紋；完成後的檔案變更需重新測試。提交、推送與建立 MR 仍由使用者操作。

MR 可選擇討論建立修正任務，固定來源／目標 SHA 與討論內容，在隔離 worktree 完成實作及測試。逐則回覆草稿可編輯並手動發布；送出前再核對版本，沿用既有標記去重與逾時對帳，並不自動解決討論。

Wiki 的「依來源變更重新產生」使用已發布頁面的來源映射。只有來源為已驗證後續版本、映射完整且變更都有對應頁面時，才重生受影響頁面與索引；其他情況全量生成。Host 保護未選取頁面的內容，發布仍需重新預覽並核對逐頁收據。

## 原生目標模式與版本能力

已停止的自由任務可設定目標及 Token 預算，並選填執行時間預算；設定後由「接續」啟動。原生 Goal 可跨 turn 接續，完成、暫停或達預算時保留狀態；時間預算會中斷目前回合並核對程序收尾。它不取代 Issue／Reviewer 的既有成果門檻。

進階能力依已捕捉的 CLI 契約啟用；目前對話分支、Goal 與用量介面驗證基準為穩定版 CLI 0.166.0。其他版本維持原入口的基本相容行為，尚未驗證的進階功能顯示原因。開發者可用 `scripts/generate-codex-protocol.mjs --codex <原生執行檔完整路徑>` 重建此固定版本的官方型別與雜湊紀錄。

Wiki、合併審查、上版檢查及 BMAD 頁面的「使用 Codex 執行」會帶入目前表單與已核對的專案根目錄。任務建立後會切到工作台的「Codex」頁，集中顯示執行訊息、命令與檔案變更、對話、核准、暫停及恢復。也可從命令選單執行「GitLab Workspace: 開啟 Codex」。

左側列出任務，中央分成「執行紀錄」與「成果」，「任務詳情」收納模型、用量、核准範圍與診斷。窄版使用任務選擇器。待回答區與輸入框保留在分頁外，背景事件不切頁或移動焦點。回覆、報告與 Wiki 可閱讀 Markdown，Wiki 另有原文及差異；程式碼可複製，檔案連結經 Repo 範圍核對後開啟對應行號。

若需要回到執行與成果同頁的排列，可在 VS Code 設定把 `gitlabWorkspace.codex.workspaceLayout` 從預設 `workspace` 改為 `classic`。切換立即生效，保留草稿、選取任務及待回答內容，不會重新啟動或重送工作。這是版面回退開關：兩種排列共用同一個準備頁、任務控制、收據及資料保護；不恢復舊版後端或原生建立精靈。改回 `workspace` 即恢復分頁工作台。

歷史與即時輸出合併更新，長工具輸出可展開。位於底部時跟隨新訊息，往上閱讀時保留位置，可按「回到最新」；「讀取更早的對話」會補入較早紀錄。

## 第一次使用

1. 安裝 Codex CLI 0.165.0 或更新版本，並信任 VS Code 工作區。
2. 在「工具與環境」的「Codex 執行環境」按「檢查 Codex」。Windows 需要可用的 Codex sandbox；尚未登入或設定完成時，使用畫面的登入及設定入口。
3. 安裝此專案對應的 WorkflowKit，並在功能頁填妥參數，按「使用 Codex 執行」。

預設從 VS Code 的 PATH 尋找相容的 Codex，支援官方 npm 安裝。若找不到，於使用者設定填寫 `gitlabWorkspace.codex.executablePath` 的完整路徑；工作區設定不會覆寫此執行檔。Provider 與既有帳號沿用本機 Codex，登入由 Codex 自行保存及更新。一般任務預選沿用本機設定，審查預選 Luna 的固定預設強度；建立前可依模型清單及套件能力修改。

## 從 GitLab 工作直接啟動

以下三個入口需要已登入 GitLab、已核對的本機 Repo、已安裝的 WorkflowKit，以及支援共用 Skills 的 Codex CLI 0.166.0+。既有 Skills／BMAD 手動入口保留。多份本機副本會在準備頁選擇；沒有副本時提供 Clone／掃描入口。

### 從 Issue 開發

在 Issue 預覽或詳情按「使用 Codex 開發」。任務會保存當下的標題、描述、標籤與版本，從專案預設分支的固定 SHA 建立 `issue/<iid>-<slug>` 分支，再由 BMAD 自動選擇流程，接續實作與測試。Repo 有未提交變更時，請先在版控保存或提交，再重新啟動。

單純產生規格不算開發完成。Host 會檢查實際差異及測試命令的退出碼，必要時接續最多三輪；仍缺少實作或成功測試時顯示「尚需接續」。Issue 原頁可查看任務及差異。提交、推送、建立 MR 和結案仍由使用者操作。排隊期間 Issue 或來源版本改變時會要求重新建立任務，原修改保留。

### 建立專案 Wiki

在 GitLab 專案列或已對應專案的本機 Repo 列按「建立／更新 Wiki」。Host 會取得遠端預設分支 SHA，以 `git archive` 建立隔離快照。Codex 的執行與寫入目錄為快照中的 `wiki/`，來源檔案不列入寫入範圍。

草稿完成後，在 Codex 頁檢查來源、頁面清單與內容；更新頁面可展開目前 GitLab 內容。只有按「發布至 GitLab Wiki」才會寫入網站。生成頁面放在 `codebase/`，不刪除其他頁面；Wiki 連結及程式來源引用會轉成 GitLab 連結。頁面內容改變後需重新預覽，部分成功及每頁收據會持續保存。

發布逾時不會自動重送。先按「重新預覽／核對結果」讀取 GitLab；已找到相同內容時會完成對帳。仍不確定時，須先在網站人工核對，再使用「確認後允許重試」。結果未明時不可刪除或接續修改這份任務。

### 一鍵 MR 審查

在 MR 詳情按「一鍵 Code Review」。Host 會取得來源與目標版本，從已驗證 remote 同步 MR ref（含 fork），建立固定的本機審查 refs，再交給 MergeReviewer；不會切換工作分支。原生報告完成後，原 MR 的審查報告分頁會讀取全文並填入空白留言草稿，既有草稿不會被覆蓋。

使用「作一般留言發布」前會再次核對原任務、帳號、來源及目標 SHA；版本改變時需重新審查。過長報告可保留完整版，將留言草稿整理為 50,000 字以內。手動選擇 Repo／分支的既有入口仍可使用。

## Reviewer 固定設定與完成檢查

建立審查任務時選擇固定模型及強度；每個 turn/start 都明確傳入該設定。Auto 已移除，既有 Auto 偏好在準備頁改選有效固定值。複製提示詞沿用 CLI 當前設定，由目前 agent 直接審查。

回合結束後，Host 核對原生 request 與發布收據。尚未發布且有保存進展時沿同 thread 接續，最多兩次；無進展則保留待續。已發布但有必要缺口的報告仍可開啟，狀態顯示尚有缺口。歷史 routing request 在核對固定身分後沿最後保存強度續作，不重 capture。

診斷保存派送模型／強度、thread／turn、送出及結束時間；服務回報的模型另行保存，未回報時保持未知。它不以路由紀錄或模型自述證明實際服務端設定。

## 執行與互動

同一實體專案根目錄的任務依序執行，其他視窗共用同一把執行鎖。排隊任務開始前會再次驗證專案及 Skills；環境已改變時需回功能頁重新確認。執行中會阻擋同根目錄內由本擴充功能管理的套件更新、下載／同步及 Git 寫入操作。

任務使用 `workspace-write` 與 `on-request`，寫入範圍包含專案及已驗證的審查 runtime／快取。命令、檔案、額外權限、Codex 問題及 MCP 表單會顯示於 Codex 頁。核准只套用本次要求，額外權限只授予目前 turn；Codex 管理政策仍會限制可用範圍。

「傳送」可在執行期間補充要求，或在本輪結束後接續同一個對話。「暫停」只影響選取任務：排隊任務移出佇列，執行中任務中斷 turn 並清理所屬程序，保留原生審查的 request、快照、草稿及已完成操作。確認程序停止後才顯示「已暫停」，其他排隊任務可繼續。「恢復」沿用原對話與審查 request ID，先核對進度再開新回合接續，並重新驗證原專案及 Skills。明確「取消」才將原生 request 設為取消，不能再自動恢復。

其他 VS Code 視窗正在執行的任務會標示執行歸屬，請回原視窗控制。關閉或重開工作台仍由原 Host 持續監聽。

「刪除紀錄」只供已停止且清理完成的任務使用。確認後一併清除該對話位於擴充功能 globalStorage 的任務紀錄、舊版備份、Wiki 草稿、來源快照及隔離 worktree，包含隔離目錄內尚未提交的修改與忽略檔案。原 Repo 的檔案、分支提交、報告與 BMAD 文件，以及 Codex 自身保存的對話均保留。其他 Wiki 任務仍需要的前版資料會先保存成該任務自己的種子。

刪除先保存最小清理清單並阻止回寫；遇到檔案占用或共用資源仍在使用時，顯示清理待重試，按「重新讀取」或下次啟動會繼續。只保留防回寫標記及必要操作去重收據。執行中、發布結果未明、程序停止未明的任務不能刪除；重新導向或無法驗證歸屬的資料保留並回報。

App Server 由建立它的操作管理，任務、環境檢查、模型清單與歷史讀取結束時會停止所屬程序；借用執行中任務連線的讀取不會關閉該連線。停止收據在所有相關鎖、排程與保存狀態完成更新後清除。Wiki 來源壓縮包解開後即清理，續作需要的來源快照則保留到刪除對話。

WorkflowKit 安裝包用畢清除；已知安裝根目錄仍使用的版本驗證工具保留，升級或移除安裝後回收不再需要的工具。清理會避開其他視窗正在使用的附件。安裝包清除後，再次安裝需要連線下載，既有版本的離線狀態檢查仍可使用保留的驗證工具。舊版 globalStorage 日誌只清理可辨識且未變動的格式，現在的原生日誌由 VS Code 管理。

## Auto-Accept

每個任務有獨立的 Auto-Accept 開關，預設 OFF。開啟後，自動核准 App Server 提供的命令執行（含網路及終端輸入核准）、檔案修改與目前回合的額外權限；只回覆單次 `accept`，不新增永久規則。一般問題、方案選擇、MCP 表單與登入仍由你回答。

開啟時也會處理當下等待中的支援核准，同一要求只回覆一次；關閉或暫停立即阻止後續自動回覆。切換頁面、暫停及恢復會保留同一 Host 的開關設定，重新載入或啟動 VS Code 後回到 OFF。自動回覆失敗時會關閉開關並提示手動核對。

時間線中的「已自動核准」表示核准已送出，操作結果仍依命令及任務狀態判定。Log 僅記錄必要任務、thread、turn、request 識別與核准範圍，不保存完整命令或提示詞。此功能在本擴充功能直接處理 App Server 核准，無須另外安裝終端版 Auto-Accept。

輸入草稿依 Host 的任務 ID 保存至 Webview state，切換任務與重建畫面均可還原。Host 確認接受或已排隊後，才清除本次送出的草稿版本；送出後繼續編輯的文字保留。blocked、failed、cancelled、unknown 均保留內容；unknown 必須先核對，不能自動重送。

「前往待回覆要求」將焦點移至目前任務的核准或回答表單；「跳至最新回覆」與「複製回覆」協助閱讀完整內容。串流不逐字播報，由獨立 polite 摘要通知完整回覆及狀態變更，背景事件不移動焦點。

## 完成、報告與恢復

「本輪完成」表示 Codex 已結束這一輪工作。合併／上版審查的報告、完整性與缺口仍以既有本機審查紀錄為準；BMAD 進度依已保存文件判斷。

進行中或可修復的審查提供「使用 Codex 恢復審查」，保留原 request ID、固定證據及 checkpoint。已終止的 request 只供檢視診斷；已發布時開啟既有報告，只有清理未完成時提供重試。「使用 Codex 重新同步」建立新的 request ID，不覆寫舊報告。

支援新啟動介面的套件會在準備任務時保存固定輸入檔，摘要與啟動命令使用同一份路徑及分支。執行前核對檔案摘要與已安裝 helper；輸入已變更時重新準備，不把既有 request 改成另一份審查。新 helper 的狀態及能力檢查使用唯讀入口；舊套件仍按其宣告的介面執行。

證據操作的完成數和語意審查待完成數分開顯示。後者是最近一次 `check` 保存的結果，不隨閱讀自動歸零。正式審查若尚有可取得的必要證據，先依 checkpoint 續查；同強度的自動修稿最多兩次，無進展的相同 checkpoint 不重跑。到達回合上限時保留待辦以供恢復，不把上限寫成證據缺失或審查完成。

關閉或收合工作台不停止任務。關閉 VS Code 會中斷工作；重新開啟後，可讀取對話，再手動續作。中斷後會先核對歷史與產物，不自動重送原始工作。結果未明或無法確認程序樹已停止時，狀態顯示「結果待核對」並保留執行鎖。

任務輸入、thread／turn ID 及收據存於本機擴充功能儲存區；完整對話由 Codex 保存，可分頁讀取。這些紀錄不寫入業務 Repo，偵錯日誌也不保存完整提示詞或認證內容。

## 開發驗證

`npm test` 包含離線協定、任務生命週期、原有功能、Webview、Extension Host 與打包驗證。一般測試不會呼叫模型。

真實 Codex 驗證另以 `npm run test:codex:live` 執行。程式會新建 `gitlab-codex-real-*` 暫存目錄、安裝固定 WorkflowKit group fixture，並建立獨立測試 Repo、VS Code 設定檔及擴充功能目錄。可用 `--vsix <安裝包>` 指定候選包。此驗證使用目前 Codex 帳號呼叫模型，操作打包後的真實 Webview，並保存 Wiki 查詢、三種 Reviewer 與 BMAD 的任務結果與截圖至 `.tmp/codex-live-*`。這個 fixture 不驗證真實 GitLab 的 Issue 開發、MR 討論修正或遠端發布；需另行驗收。

Live fixture 只會核准白名單中的唯讀 Git 命令，且須核對原始要求的執行目錄正好是 fixture 根目錄或其 `service` Repo。額外權限、檔案寫入核准、網路或其他未列出的要求會取消並令驗證失敗，交由人工審查；不以命令文字是否包含網址判定安全。Auto-Accept 開關只在已暫停並確認清理後測試，恢復前保持關閉。主要 GitLab 工作流程的端到端驗收仍需明確指定測試專案及遠端／模型呼叫授權。

通訊以 [官方 Codex App Server 協定](https://learn.chatgpt.com/docs/app-server)的 stdio 模式實作，首版測試基準為 CLI 0.165.0。CLI 不相容、未登入或環境未完成時，仍可使用原有複製提示詞功能。
