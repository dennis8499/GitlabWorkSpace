# 疑難排解

## 無法連線或驗證 Token 失敗

- 確認輸入完整網址，並使用 `http://` 或 `https://`。網址不可包含帳號密碼、查詢參數或片段。
- 確認 Token 尚未撤銷，且具有 `api` 範圍；登入帳號需有權存取所選群組。
- 若 GitLab 使用自架網域或安裝於子路徑，請在網址中包含正確主機、連接埠及路徑。
- HTTP 不會加密 Token 傳輸。可改用 HTTPS，或確認目前網路環境可信任。
- Token 只有在 `GET /user` 驗證成功後才會儲存。修正網址或 Token 後重新執行 **GitLab Workspace: Connect**。

## 沒有看到群組或專案

- 確認 GitLab 帳號已加入預期的群組，並重新選擇 **Select Group**。
- 展開群組並確認它包含專案。清單會包括子群組中的專案。
- 執行 **GitLab Workspace: Refresh** 重新載入資料。
- 若伺服器拒絕 API 請求，依訊息檢查 Token 範圍、帳號存取權及 GitLab 連線狀態。

## **My Issues** 是空的

清單只顯示「目前帳號被指派」且位於「所選群組專案」中的開啟或已關閉議題。請確認議題指派對象及所選群組，再重新整理清單。未指派給自己的新議題會在建立後直接開啟，但不會列入 **My Issues**。

## 找不到複製命令或 Git 無法啟動

- 先連線並選擇群組。群組未選定時，複製全部及複製勾選項目的命令不會顯示。
- 確認 Git 已安裝，並在新的終端機執行 `git --version`。若終端機找不到 Git，將 Git 加入 `PATH` 後重新啟動 VS Code。
- 確認帳號具有目標專案的讀取權限。若複製私有專案，Token 必須能以該帳號存取它。

## Clone 或更新因目的地衝突而停止

開始前會檢查整批專案的資料夾名稱與目的地。已存在的資料夾必須是對應專案的 Git Repo，且 origin 必須指向該專案的 HTTPS 或 SSH clone URL；一般資料夾、其他 Repo、符號連結或名稱重複會讓整批停止。檢查並處理衝突目錄後，再重新執行。

有本機修改、未追蹤檔案或分支分歧的 Repo 會被略過，其他項目仍會繼續。從完成通知選擇 **Show Details** 可查看每個略過原因。若 Clone 或 Git 更新開始後失敗，已完成的項目會保留，後續項目會略過；先確認網路、Token 和專案權限，再重試。

## 議題操作或子功能不可用

- 編輯、留言、移動、複製與刪除按鈕依 GitLab 帳號權限顯示；請確認帳號在該專案的角色及議題權限。
- 子工作項目、開始日期或討論串解決功能會依 GitLab 版本與 API 能力而異。連線提示或議題畫面訊息會指出目前無法使用的能力。
- 操作失敗時，先閱讀畫面中的 GitLab 錯誤訊息，再用 **GitLab Workspace: Refresh** 重新載入後重試。
