# 0.54.0

重新設計專案批次更新與 Codex 工作台，保留主要操作空間，並提供可持續保存的執行紀錄刪除。

## 專案更新

- 「更新全部本機預設分支」改用底部精簡狀態列，確認、執行及完成時保留專案清單的大小、選取與捲動位置。
- 結果詳情按需開啟，可篩選全部、失敗及略過項目，閱讀完整錯誤、取消執行或關閉後重新開啟。
- 短視窗改用模態詳情，支援鍵盤焦點移動、Escape 關閉及焦點返回。

## Codex 工作台與紀錄管理

- 整理為任務清單與對話，主要操作集中，次要資訊收進詳情；窄視窗使用任務抽屜。
- 修正 VS Code 1.90.0 在 200% 縮放、極短視窗下輸入框取得焦點後仍被裁切的問題；短視窗使用單一主要捲動區，保留完整核准內容與可見焦點。
- 任務列直接刪除，管理模式支援按目前篩選批次選取，每次最多 1,000 筆。原生確認後逐筆核對，部分失敗可重試。
- 執行中任務須先停止。刪除清除擴充功能的任務、對話紀錄、草稿及所屬暫存，保留原專案程式碼、成果包與已匯出檔案；外部、共享或無法證明權屬的 CLI 對話保留。
- 持續保存刪除狀態，避免重開視窗、延遲輸出或舊快照重新顯示紀錄。發布結果不明或清理失敗時保留資料供核對／重試，重新啟動只恢復清理，不重新呼叫模型或發布。
- 批次處理選取中對話的串流更新，降低捲動狀態寫入頻率，保留草稿、閱讀位置與切換任務時的焦點。

## 升級

安裝後請重新載入所有開啟 GitLab Workspace 的 VS Code 視窗，再使用刪除紀錄。舊 Host 不識別新的紀錄刪除狀態；降回舊版也可能重新顯示已保留成果的紀錄。

## 驗證與正式附件

本輪本機完整驗證通過 1,945 項單元測試（4 項既有跳過）、416 項介面行為測試、23 項 Extension Host 測試及額外 12 組原生縮放／主題案例；工作區信任、Cucumber、WorkflowKit 安裝／回復、發行工具、封裝與套件檢查亦通過。包含 100 輪生命週期競態測試，共 300 次派送。CI 發現的最低支援版短視窗焦點問題另補上 464×272、320×272、464×400 及縮放／主題切換回歸，完整矩陣須重新通過才發布。

本機渲染比較使用正式 bundle 與合成 Host，驗證 2,000／10,000 筆對話及串流中的輸入、任務切換、草稿與閱讀位置；相同捲動情境的狀態寫入由 48 次降至 1 次。此量測不代表真實 GitLab、模型或網路延遲。NVDA 尚未實測。

正式附件只提供經完整 CI 矩陣驗證的 VSIX 與 `SHA256SUMS`；來源提交及附件摘要以 GitHub Release 的 Verification 區段為準。
