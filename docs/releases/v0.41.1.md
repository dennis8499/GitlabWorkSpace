# GitLab Workspace 0.41.1

本版改善 Wiki 核對中斷後的續載，以及大量 Codex 對話的畫面與歷史讀取效能。原生命令、設定、草稿格式與發布前的版本檢查維持相容。

## 變更

- Wiki 每頁核對後立即保存並更新進度。失敗、取消或達到批次預算後，可接續剩餘頁面，不重讀已完成頁面；新增停止與繼續核對操作。核對未完成時不可發布。
- Wiki 與成果讀取在隱藏、離頁、切換帳號或根目錄後取消；隱藏後才抵達的排隊讀取也不會重新啟動。已接受的發布可完成，保留遠端版本重驗、逐頁收據與未知結果核對。
- Codex 使用可變高度虛擬清單與訊息識別索引，保留切換任務、重開 Webview、歷史前插和持續輸出時的閱讀位置，以及鍵盤焦點、展開狀態與草稿。
- 歷史頁採 60 秒、依任務版本與游標隔離的快取，合併進行中請求；命中快取不新建 App Server。明確讀取可略過快取，相同 Wiki 結果不再改寫任務時間戳而使快取失效。
- 拆出 Wiki／Codex 工作流程服務，集中讀取取消與發布檢查；BMAD Controller、Reader 及 YAML／TOML 解析器改為按需載入。
- 窄畫面 Wiki 預覽維持可讀高度，焦點移到輸入框時可將其捲入可見範圍。Host 型別、訊息驗證與操作政策同步更新。

## 驗證與限制

- 本機 Lint、Host 編譯、Webview 型別與建置通過；完整單元 **1,170 通過、3 跳過**，Webview 行為 **248 通過**，Cucumber **39 情境、171 步驟通過**。
- 正式 bundle 搭配模擬 Host 的 10,000 筆對話測試，批次更新 p95 由 **186.9ms 降至 31.9ms**，本次 1280×900 fixture 掛載 16 列。數字不包含原生輸入、VS Code bridge、GitLab 或模型等待。
- 八模式、四類主題與三種寬度，加上 Wiki 狀態共 **128 組**畫面檢查通過，另有 **32 組**窄畫面焦點檢查通過。
- 兩個 VS Code 版本與本機／OneDrive 產物的四組 BMAD 專項通過，最慢 641–817ms；穩定版整套回歸仍曾量到 **1,155ms**。本機完整宿主另有 WorkflowKit 安裝逾時與 Folder Settings 錯誤，不能以專項通過取代完整驗收。
- 本機完整原生宿主與離線 Python 安裝整合未宣稱通過。正式附件仍由既有 GitHub Actions 完整矩陣驗證後發布；不調寬門檻或略過驗證。
- 原生 240／320px、實際 125%／200% 縮放、NVDA、真實 GitLab 發布及真實模型延遲尚未驗收。

完整實作、量測方法及本機失敗紀錄見 [驗證報告](../work/work-20261106-extension-performance/verification.md)。報告保留測試當時的 0.41.0 工作樹與本機產物身分；本版僅另調整發布版本與本說明，正式 Release 的 commit、CI 與附件雜湊以發布頁的驗證資料為準。
