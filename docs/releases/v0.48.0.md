# GitlabWorkSpace 0.48.0

分支審查的路徑、分支與安裝身分使用同一份固定輸入，修正重新輸入長命令可能遺漏目錄的問題。

- 配合宣告新啟動能力的 WorkflowKit／MergeReviewer，準備時保存 `ReviewLaunchRequest/v1`，提示詞只帶輸入檔與 SHA-256；摘要與執行使用相同欄位。啟動檔位於 runner 的獨立暫存目錄，建立任務時不進行擷取或同步。舊版套件維持原有 CLI。
- 審查操作依持久狀態判斷：已終止的 request 不再顯示恢復按鈕，Host 也會拒絕恢復；已發布報告直接開啟，只有清理未完成時提供重試。保留的診斷暫存可明確清理，重新同步建立新 request。
- 畫面分別顯示證據操作進度及最近一次檢查的必要待完成數；沒有保存的數字維持未知，不把操作讀完算成語意審查完成。
- runner 可寫暫存目錄不再依賴 Model Routing 是否啟用，已發布後重試清理也保留所需目錄。支援的能力探測使用唯讀入口。Windows 暫時清理錯誤採有限重試並重驗目錄所有權，穩定重新導向仍會拒絕。
- 原生審查終止後，保留模型及強度稽核資訊，畫面顯示已終止；這些紀錄不允許重新派送。正式審查的續作讀取持久 checkpoint，未取得進展的同一 checkpoint 不自動重跑。

此版本仍依原生收據區分報告發布與審查完整性。語法分析維持安裝版驗收設定；本機封裝只供驗證，遠端發行狀態與正式安裝資產以 v0.48.0 GitHub Release 為準。

測試與量測範圍見 [驗證紀錄](../work/work-20261110-reviewer-reliability/verification.md)。
