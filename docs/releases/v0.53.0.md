# 0.53.0

透過本機 Codex CLI 的 App Server，在原 Group／Repo 視窗準備、執行及檢閱任務。適用於以 VS Code 開啟 Group 下載根目錄、公司環境僅安裝 Codex CLI 的使用方式。

## 任務與本機核准

- 新任務在原視窗執行，清楚顯示來源、執行與成果位置；另窗瀏覽不會接管或重送任務。重開只恢復歸屬與狀態，須明確接續才執行。
- Issue 實作與 MR 討論修正使用獨立 Clone，共用來源快取；既有 managed worktree 保持相容。
- 新增機器設定 `gitlabWorkspace.codex.autoApproveLocalOperations`，首次預設關閉，只決定新任務預設。每個任務保存自己的開關；暫停或重開後須明確執行才啟用。
- 自動核准限於已知、符合固定任務範圍的命令與檔案修改；額外權限、網路權限、問題及登入由使用者處理，GitLab 成果交付另須確認。不需另外啟動終端版 Auto-Accept。
- 執行期間阻擋會改變任務情境的帳號、Group 及根目錄操作；外部根目錄設定變動會暫停所屬任務。
- 依捕捉並測試的契約啟用 Codex CLI 0.169.0 原生對話刪除；其他進階能力維持各自版本門檻。

## 單一 Repo 的兩種 Wiki

- 本地 Codebase Wiki 在 Group 視窗選單一 Repo，只攝入該來源並保存在 Group 共用 `wiki/`；直接開啟 Repo 時保存在該 Repo 的 `wiki/`。
- 完整所選 Repo 使用自己的 coverage ledger，局部路徑更新保留其他範圍；來源越界或未映射頁面會使品質檢查失敗，保留實際變更供檢閱。
- GitLab Wiki 使用目前預設分支的固定 SHA 建立草稿，檢閱後才發布。來源映射與發布基準永久保存在成果中，暫存清理後仍能建立增量更新任務；舊成果缺少映射時明示全量生成。
- 本地 Wiki 成果保存這次修改的 Markdown 及必要 Wiki 附件，不宣稱是完整 Wiki 備份。兩種 Wiki 的入口、保存位置與發布行為分開呈現。

## 操作與復原

- 調整下載位置資訊、任務主操作、驗證紀錄及下一步呈現，阻擋尚未確定的交付與耗盡驗證輪次後的自動續作。
- 修正 Wiki 發布結果不明時無法核對的問題：可重新預覽、繼續核對及檢閱原文／差異，未核對前不重複發布。
- 改善短高度版面的捲動與輸入列，驗證原生四種主題及三種縮放，共 12 組操作案例。

## 驗證與正式附件

本機分項驗證通過 238 項受影響單元測試、398 項介面行為、40 個 BDD 情境、19 項原生 Host 測試、工作區信任檢查及五版 WorkflowKit 相容安裝；包含全部 12 組原生主題／縮放。完整矩陣的正式來源與附件 digest 以本 Release 的 Verification 區段為準，僅發布經 CI 驗證的 VSIX 與 `SHA256SUMS`。

公司 GitLab 實際發布、真實模型及其他作業系統未在本機驗收；另有五項需額外啟用的實機測試未執行。詳細分項及先前失敗／補驗紀錄見[驗證範圍](../work/work-20261116-cli-group-flow/verification.md)。
