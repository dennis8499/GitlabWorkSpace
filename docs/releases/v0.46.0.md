# GitlabWorkSpace 0.46.0

減少日常驗證與環境偵測的重複工作，完整保留正式發行所需的相容性、完整性及安全檢查。

- 新增 `test:quick`、`test:ui`、`test:compatibility` 與 `test:legacy`。PR 依受信任基準的變更分類選擇檢查；main、版本標籤與手動流程仍執行完整三組 Windows 矩陣。快速結果不產生正式發布證據。
- WorkflowKit Python 整合分成三個獨立工作，保留全部 16 個案例與程序隔離；固定附件在每個程序首次使用時驗證版本、大小與 SHA-256。舊 Webview 側欄移至明確選用的歷史測試，正式建置只產生目前使用的介面。
- BMAD 操作只做一次最終流程讀取；Python 同時請求及單次操作內共用探測結果，操作結束後清除。寫入前的根目錄、revision、權限與完整性檢查保留。
- Cucumber 改為等待畫面或對應訊息完成；建立子工作、加入既有子工作及建立關聯後，只清除仍等於提交值的欄位，保留等待期間輸入的新草稿。
- Codex 啟動重用有效的本機環境資訊與執行中連線，減少重複初始化；長對話顯示改善列高與捲動定位，避免輸出重疊。
- prepared 收據升級為 v2，在取得工作目錄鎖後核對來源與產物，重疊輸出只計算一次摘要。舊收據需重新執行 `npm run prepare:validation`。

本機快速流程三輪中位為 155.895 秒，完整回歸約 33 分鐘；兩者涵蓋範圍不同，不代表完整檢查可縮減至相同時間。原生 Host、Workspace Trust、單元、正式 Webview 行為、發行整合、最低支援版 VS Code 1.90 核心與歷史側欄測試已通過，既有平台限定及需額外環境的案例維持明確跳過／待啟用狀態。量測與範圍見 [驗證紀錄](../work/work-20261109-validation-efficiency/verification.md)。

正式附件由此版本提交的完整 GitHub Actions 矩陣產生，發布前核對來源、版本與附件 SHA-256；本機驗證不替代正式 CI 證明。
