# 0.54.2

修正 API 控制鎖釋放失敗後，後續登入遇到 `metadata-missing / ENOENT` 的問題，並改善現場診斷與離線復原。

## 連線與復原

- API 控制鎖保留擁有者資訊，先更名至唯一舊目錄再清理，避免先刪 metadata 後留下阻塞連線的空鎖。
- 更名成功即完成控制鎖釋放；舊目錄清理失敗只記錄警告，不阻擋新請求或改判已確認的寫入。重複釋放不影響新擁有者。
- 確認已結束的 API 控制程序使用相同回收流程；額度、冷卻及其他請求預約保留。
- Log 增加實際 `leasePath`；原生登入成功、失敗與取消的紀錄與操作結果一致。
- VSIX 內附預設僅檢查的 PowerShell 復原工具。既有未知鎖須在所有相關客戶端停止後，明確指定確認為空的 API 控制鎖才能移除；非空鎖保留診斷。詳見[操作步驟](../network-policy.md#api-控制鎖離線復原)。

## 安裝與驗證

本機附件為 `gitlab-workspace-0.54.2.vsix` 與 `SHA256SUMS`；復原工具包含於 VSIX，校驗檔沿用只記錄 VSIX 的格式。安裝後重新啟動所有相關 VS Code 視窗。

完整本機驗證使用 `npm test`。正式發布仍須另外通過既有三組 CI 矩陣；本機驗證不代替正式發布證據。出錯電腦的離線檢查及重新連線須由現場另行驗收。
