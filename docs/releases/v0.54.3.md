# 0.54.3

整合本機 GitLab 連線復原流程。更新擴充功能會防止新的空鎖，但既有 `metadata-missing` 鎖仍須檢查；本版提供直接復原入口。

- 登入、新增帳號及切換帳號遇到尚未送出請求的缺少 owner 錯誤時，通知與訊息中心提供「修復本機連線」。
- 命令面板可執行「GitLab Workspace: 修復本機 GitLab 連線」，不需先登入或開啟專案。
- Windows 會開啟獨立 PowerShell。依其中提示保存工作、停止任務並關閉所有相關客戶端，輸入 Y 確認後，只移除經再次檢查為空的指定 API 控制鎖，再自行重開 VS Code 登入。
- 工具保留非空鎖、隱藏檔案、權限或程序狀態不明的資料；鎖已不存在時回報 Missing。取消不進行修復。
- 通知可將先前的 Log 入口升級為復原入口，且不重複回執。啟動 Log 記錄擴充功能版本；開啟復原視窗不代表修復完成，也不自動重送請求。

本機附件為 `gitlab-workspace-0.54.3.vsix` 與 `SHA256SUMS`。操作與相容命令見[本機連線復原文件](../network-policy.md#api-控制鎖離線復原)。正式發布沿用既有完整 CI 矩陣；出錯電腦的實際目錄與重連結果須在現場驗收。
