# 0.52.0

改善需求探索、Issue 實作、MergeReviewer、ReleaseReviewer 與本地 Codebase LLM Wiki 的接續與驗收。保留既有獨立工具入口、首次準備與後續一鍵啟動，不要求每個任務建立完整工作流程。

## 需求、驗證與交付

- 受管理工作保存唯讀需求快照、穩定驗收 ID 及內容摘要；來源內容改變時，舊證據失效。GitLab 寫入前重新核對來源，仍須人工檢閱確認。
- 實作與驗證合計最多三輪，保存真實命令、退出碼、失敗及中斷證據，重新啟動不重設上限。只有規格的任務先接續實作；缺少依賴、權限或命令證據時停止自動修復。
- 需求已由現有程式滿足且核定檢查通過時，可無差異完成，不建立空 commit 或 MR。未設定自動檢查命令的純文件變更，可檢閱差異後明確人工驗收，不捏造測試成功；混合程式變更仍須實際檢查。
- 已建立 Issue 及已交付 Draft MR 提供明確下一步，兩種 Reviewer 保持不同意圖。下一步綁定原帳號及站台；舊成果缺少範圍時只開啟原始 URL，不自動執行。

## 本地 Wiki 與工作效率

- 從命令選單、本機 Repo 列及原生右鍵選單開啟本地 Wiki，無須登入 GitLab；查詢、建立／更新及品質檢查沿用一般任務準備流程。
- Group 共用 Wiki，Repo 操作限定來源範圍。查詢及品質檢查唯讀；更新、重建索引與 NotebookLM 匯出只授權各自輸出目錄，不授權原始碼寫入。
- 真實品質 helpers 的完整收據保存在任務及成果封存，介面只傳送摘要。既有人工備註標記區塊持續受到保護；未標記人工正文仍沿用框架的保留規則。
- 相同固定提交可重用已驗證的 archive 與 tree index，各任務輸出仍獨立。驗證命令只提出建議，使用者明確採納後才使用。
- Webview 加入 Host／Node 匯入限制；原生 Reviewer launcher 使用實際 `ReviewLaunchMetrics/v1` 計時，缺資料保持未知，不當作工作完成證據。

## 驗證與正式附件

本機最終針對性回歸 349 項、交付保護 4 項、原生 Host 補驗 6 項及發行相容檢查均通過，包含 12 組原生主題／縮放案例。較早完整 UI 分項為 1,848 項單元通過／4 項略過、391 項介面行為及 40 個 BDD 情境；該 run 最後正確拒絕過期 prepared build，完整命令仍保留為失敗。後續已重新準備並通過本機套件驗證，沒有將原失敗改寫為成功。

本輪未執行真實 GitLab 發布、付費模型、NVDA 或其他作業系統驗收；真實 Codex sandbox 的 Wiki 權限組合仍需實機核對。完整分項證據與界線見[驗證紀錄](../work/work-20261115-workflow-experience/verification.md)。

正式 Release 由完整 Windows／Python／VS Code 矩陣通過後提升相同的已驗證附件，僅包含 `gitlab-workspace-0.52.0.vsix` 與 `SHA256SUMS`；WorkflowKit 整合包沿用其獨立 Release。本機 0.51.0 候選套件僅是前一階段的驗證產物，不作為本次正式附件。
