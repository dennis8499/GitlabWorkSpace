草稿／圖譜單一草稿保存入口保留最後輸入；穩定 callbacks／keys；>500 節點 Worker 佈局、Canvas 視野裁切、搜尋與鍵盤；原生隱藏銷毀、恢復重建與卸載清理；主題色及高對比。
Skills／BMAD／附件保留安裝交易復原；BMAD 可取消讀取、內容／解析快取與相關檔案索引，執行和人工確認前重新核對；附件 stat 後串流、50 MiB 上限與取消生命週期。
日誌／通知／操作復原合併追加和清理、可重建段索引與取消查詢／匯出；通知去重有界；1000 筆記憶體操作歷史與 256 bucket 磁碟收據，保留 active／unknown，重啟核對不重送。
工作台傳輸初始化／復原完整 snapshot，後續具 scope、stream、baseVersion/version 的 patch；缺版請求 resync；小變更不再重傳大型清單。

驗收限制與待驗

缺少專用 GitLab Token；真實 GitLab 寫入與完整實機效能門檻維持待驗。功能矩陣有 19 項的六種離線情境已齊全，38 項仍有待驗情境。
  • 真實 GitLab CE 16.11.10 與其他實機環境的隔離測試帳號／群組讀寫、權限及未知寫入核對。
  • 各真實環境 10 次冷啟動、每輪 30 次暖切頁與搜尋；含 Extension Host、GitLab 網路及完整峰值記憶體。
  • 工作台骨架／離線入口 p95 ≤1 秒，以及全部隱藏／取消路徑 ≤1 秒的實機量測。
  • 矩陣中仍為 pending 的逐項取消、重試、範圍切換或恢復情境；完整測試通過不會自動提升這些狀態。
  • 封裝 Renderer 比較使用 20 Repo 的隔離 mock host，10 個新 Browser context，每輪 30 次暖切頁及搜尋；不是 10 次真實 VS Code 程序冷啟動。
  • Renderer 記憶體是 GC 後 retained heap；不等於 Extension Host 或整個應用程式峰值。
  • 工作台快照量測涵蓋 50/500/2000 Repo 與 100/1000/10000 Issue，僅量測 host 計算與 JSON 序列化；壓力負載只有 3 筆，未報 p95。
  • 圖譜比較每負載 3 輪，選取共 90 筆、縮放共 45 筆；2000 節點以 Canvas/Worker 執行，初始掛載仍可出現 >50 ms 長任務。
  • 早期 sandbox 啟動失敗、舊 fixture 及已修正的回歸失敗保留於原始 optimization 目錄；此報告引用最後完整通過的一輪。
