# Windows acceptance

Supported architecture: x64. Required Windows baselines: Windows 10 22H2 and Windows 11 24H2/25H2. Automated Windows jobs use Windows Server 2022 as the runner image, so those results are compatibility regression evidence and do not replace desktop Windows acceptance.

On each supported desktop Windows version, run `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/windows-acceptance.ps1` from the repository. The script runs the full test and package suite, checks Node, Python, Git, VS Code and operating system versions, exercises a temporary Group workspace with Chinese characters and spaces, mixed line endings and a Windows junction, installs the resulting VSIX into disposable VS Code user data and extension directories, and writes its JSON evidence and VSIX SHA-256 under `dist/`.

Use a dedicated GitLab test project for authenticated acceptance. Keep the tests inside that project and record its permissions and GitLab version without recording tokens.

| Feature | Acceptance check |
| --- | --- |
| Connection and group selection | Connect with a test account; select and refresh a group with nested projects. Confirm invalid credentials and HTTP failures leave the previous saved connection intact. |
| Account UI | Verify the permanent sidebar identity summary, quick account menu and shared settings panel at narrow and normal widths in light and dark themes. Exercise both login steps, Token visibility, validation errors and retry, expired accounts, reauthentication identity checks, switching, logout and removal. Confirm keyboard tab navigation, Escape and focus restoration; closing or submitting the form must clear the Token without persisting it in Webview state or logs. Login success and Group/workspace readiness must be shown separately. |
| Skills project root | Confirm downloads, Skills installation/execution and Codex use the same selected project root. A Git root uses the repository profile; a regular directory uses the Group profile. Login, selected remote Group and mixed or missing origins do not select the local profile. Multiple workspace folders require an explicit folder choice; a Repo subdirectory is rejected without climbing to its parent. Verify setting races, worktrees and remote changes; no separate Skills Repo selector or Group-mode toggle appears. Downloads/imports remain available offline. |
| Projects and Git | Clone, update and sync a same-named child-group repo. Check HTTP and SSH remotes, dirty worktrees, case-only path differences, Unicode folder names, a path containing spaces, and preflight behavior for existing folders. |
| Issues and discussions | Create an unassigned Issue, open its detail, edit it, attach a file, add and reply to a discussion, and exercise permission-dependent lifecycle and relationship controls. Confirm failed writes preserve the entered draft. |
| Skills guide | Verify three tool tabs, four installed Skills and fourteen guide capabilities in both profiles, with actual bundle/upstream versions. Native prompts, Wiki and Codex cwd use the selected Repo and exclude Group contracts. Preserve drafts across Group/Repo switches and reopening. Older bundles require an update; old development jobs cannot resume. Recheck context before copy and launch. |
| Removed integration | Verify three tool tabs and Query as the default. Restore old development selections to Query and old Issue development tabs to Content. Upgrade removes only verified unchanged managed files; preserve work records, locks, exports and independent Skills. Verify interrupted deletion recovery and rollback. |
| Issue Board and graph | Filter assigned Issues by Group Issue Board, switch between list and relationship graph, filter by Board, open a graph node, and check partial-load states, related Issue preservation, and retry controls on desktop layouts. |
| Time tracking | Start, pause and resume a timer; create, edit, submit and reconcile a manual entry. Confirm an uncertain submission is not retried automatically. |
| MR review | Verify fixed-version reports, manual comments and source/target SHA checks. Confirm approval and merge use existing GitLab permissions and head SHA rules. Generic Git operations remain available. |
| Release tools | Use bundled TAR.XZ and imported ZIP for both group and repository profiles. Native installs require an actual workspace Git root (including worktrees), never arbitrary folders or subdirectories. Verify profile conversion in both directions, supported historical and pre-removal baselines, transaction rollback and interrupted recovery, and local modification rejection. Unfinished development records do not block upgrades. Preserve Wiki, personal Skills, work records and reports. UI navigation never installs. Another root’s installation must not enable features or supply its version. Validate source pins, both payload hashes, malformed archives, capacities, managed conflicts and deterministic rebuilds. |

The local GitLab instance currently responds to unauthenticated requests, but a valid isolated test project and test token are still required for authenticated acceptance. Windows 10 22H2 and a live Gitea connection remain explicitly pending until those environments are available.
