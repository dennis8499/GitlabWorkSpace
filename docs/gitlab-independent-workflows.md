# GitLab 不可用時的功能

開啟本機專案後，可直接從「儲存庫」、Command Palette 或工作台進入本機功能。GitLab 是專案、Issue、MR 及遠端發布的選用整合；其登入狀態不決定本機專案的位置。

| 功能 | 可用條件 |
| --- | --- |
| 總覽、設定、帳號管理、訊息中心、Log | 不需要 GitLab 帳號或 Group |
| Repo 掃描、搜尋、選擇 | 本機專案資料夾與 Git |
| Git 差異、暫存、提交、分支、歷史、Stash | Git 與可操作的 Repo；保留衝突、未存檔及寫入鎖檢查 |
| Codex、Skills、Wiki、BMAD | 各自已準備的套件、Python／Node.js、Codex 登入及模型服務 |
| 分支審查、ReleaseReviewer、CommitReviewer | 已安裝的工具；遠端分支可能需要 Fetch；Commit 草稿仍要求 Issue 引用 |
| Git Fetch、Pull、Push、帶 Fetch 的 Rebase／預覽 | 遠端可達與該遠端的 Git 認證，不要求 GitLab Group 清單 |
| WorkflowKit 狀態 | 本機安裝與 Python；下載／更新另需要 GitHub 或 Gitea 來源可達 |
| GitLab 專案清單、Group 批次 Clone／同步、Issue／MR、遠端發布 | 有效的 GitLab 登入、連線及該資源權限 |

## 登入狀態與工作延續

狀態會區分尚未設定、尚未驗證、正在連線、已連線、需要重新登入及暫時無法連線。保存過帳號資料不代表本次啟動已驗證登入。單一資源無權限、版本資訊或可選 Schema 探測失敗，不會停用其他本機功能。

登入、登出或切換 GitLab 帳號／Group 時，純本機任務繼續使用原根目錄，保留草稿、選取與閱讀狀態。正在使用 GitLab 授權的任務、遠端寫入及待確認發布結果，仍須先停止或核對。更換專案根目錄、更新 Skills 及同 Repo 寫入的限制繼續適用。

Git 遠端操作在開始前固定認證來源，不會在多步驟命令途中改用剛切換的帳號。尚未驗證或已失效的 Extension Token 不會注入新操作，可沿用 Git credential helper 或 SSH 的獨立認證。失敗的 Push 不會自動改憑證重送。

## 本機成果

永久成果包沿用既有保存及完整匯出方式。尚未封存的 GitLab 關聯任務，可在原專案閱讀與匯出已保存的報告、交接摘要或 Wiki 文件；介面會標示本機唯讀內容及原專案／來源版本。這些內容不表示遠端仍為同一版本或目前帳號具有發布權限。

閱讀成果不啟動 Codex CLI、模型、遠端來源檢查或任務清理。未封存文件匯出到新的目錄，保留原任務；沒有文件或路徑無法確認時，顯示原因。接續與發布須回到原帳號並重新核對來源。程序停止與人工接手仍可由既有本機連線管理入口處理。

## 草稿保存與恢復

本機輸入依所選工作區資料夾及實際根目錄保存；GitLab 關聯的回答、留言與任務準備另依帳號隔離。切換帳號會讀取對應的遠端輸入，純本機輸入保持原內容。

能確認歸屬的舊草稿會複製到新範圍，原件保留；跨視窗內容衝突可在 Codex 草稿保存區選擇要保留的版本。不明歸屬、已刪除任務及待確認的送出收據不會被轉成新的執行操作。

本功能不建立 Issue／MR 離線資料庫或自動同步佇列。恢復連線後，GitLab 發布仍由使用者明確觸發。Workspace Trust 與虛擬工作區限制繼續適用。
