# 按需載入與操作回饋

一般切頁會重用有效資料。Issue、MR 摘要與 Issue 搜尋結果保留 60 秒；專案清單與新增 Issue 的專案搜尋、欄位選項及已核對的固定版本 Diff 保留五分鐘。目標專案搜尋維持 60 秒。期限到達只顯示「下次需要時更新」，頁面停留不會自行刷新。手動更新仍會重新讀取目前需要的資料。

「待審查」的全部、指定我為 Reviewer、指派給我直接查詢對應結果。清單只顯示已載入的範圍；需要其餘結果時按「載入更多」。搜尋及 Issue 欄位選項每次讀一頁，切換條件後舊結果不會混入。

新增 Issue 不必先載入整個 Group。可先填寫標題與描述，再搜尋專案；成員、標籤、里程碑與範本分別按需載入。換專案或載入更多後，草稿與已選值保留。

資料旁會顯示取得時間及快取、GitLab 或混合來源。遇到排隊或限流時，介面顯示目前傳輸階段；倒數結束後可以明確重試。按鈕與抽屜的過場不會發起資料讀取，減少動態效果時會立即切換。

Git 的 ↑↓ 表示本機追蹤分支資訊。最近成功 Fetch 僅記錄本次工作台觀察到的操作，外部工具同步不會被推定成工作台曾經 Fetch。搜尋、勾選與瀏覽本機清單不連 Git Server。

## GitLab CE 16.11.10 驗收

驗收目標與正式最低支援版本統一為 CE 16.11.10，版本釘選合約與既有正向能力測試使用此版本。完整 CE Schema 與精確版本實機驗收仍須在隔離測試環境完成。Community Edition 不提供本工具使用的 MR 核准 API，相關操作會停用；版別未知時先重新檢查站台資料。

實機測試預設為 CE 16.11.10。驗收時在測試程序設定 `GLW_CE16_URL`、`GLW_CE16_EXPECTED_VERSION=16.11.10` 與既有 `GLW_CE16_TOKEN`，再使用原本的 `--environment ce16` 流程。測試會嚴格核對伺服器版號及 CE 版別，並在證據記錄實際目標；其他修補版本不能代替。沒有 Token 不會執行已登入的實機測試。
