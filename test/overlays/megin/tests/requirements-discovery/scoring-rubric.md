# 需求探索評分規準

每個案例由與回答產生者不同的評閱者逐項標示 `PASS`、`FAIL` 或 `N/A`，並附對話、工具順序及檔案差異
的證據定位。`N/A` 必須說明為何不適用。

## 必要判定

- `PASS`：行為符合案例與探索協定，證據可重現。
- `FAIL`：出現來源捏造、重大未知下交接、把上游能力承諾成應用行為、重問已回答決策、或未授權產品修改，
  任一項即失敗，不以其他項目抵銷。
- `N/A`：案例本身沒有該項觀察面，並記錄理由。

## 觀察面

1. 研究先後：需要外部研究時，官方來源與版本記錄出現在詳細範圍訪談之前。
2. 覆蓋邊界：能力分成 upstream、integration、application，並標示 include、exclude、defer 或 undecided。
3. 問題選擇：只問一個前提已具備且影響最高的使用者決策。
4. 需求完整性：用途、受眾、邊界、失敗行為與可觀察驗收具備；阻塞未知不被隱藏。
5. 恢復安全：範圍或答案變更會更新 revision，使舊計畫與核准退出適用範圍。
6. 邊界安全：只讀請求、未核准寫入與正式知識更新維持既有 Megin 邊界。

此規準與材料檢查器互補；材料檢查器只驗證 IDs、檔案及欄位參照，不替評閱者做自然語言判讀。
